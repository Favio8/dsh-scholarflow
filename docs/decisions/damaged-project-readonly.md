# 损坏项目只读诊断

日期：2026-10-05。依据 PRD SF-028、SF-030，SPEC 5、9、26、33 的原文件保护和禁止默认空数据覆盖约束。高版本原文件查看由 future-schema-readonly.md 记录；本实现补齐损坏记录。

当前会话仍必须属于所选 Host 工作区且为 ScholarFlow Mode。配置无法解释时只提供该工作区元数据读取，不猜测项目身份或输出路径；配置头能够安全校验时才读取明确声明、位于专属目录、非敏感的 Markdown／BibTeX 输出。配置、ledger、资源锁、事务日志不执行、不恢复、不创建默认数据。诊断 gateway 拒绝 write 与 lock，拒绝发生在任何原生锁元数据或 Host 内容写入之前。

ledger、配置、资源锁、身份或正文记录失败时切换为只读页面。损坏事务在原文件展示中保留，不能绕过第三方改稿冲突。每份诊断文件最多二 MiB，事务目录最多一百条，不展开未知名称或任意材料路径。无法作为完整 UTF-8 读取的文件提示限制，不替换编码、不用损失性文本导出冒充原字节。正常 UTF-8 原文件保留 BOM、CRLF 与未知字段，下载以完整内容摘要核对。显示前重验读取版本，文件改变时拒绝旧诊断快照。

正常写入的 Host 绑定检查先确认事务状态与当前项目数据；未完成的有效事务仍允许经过原授权恢复流程，不被初始化期间暂缺 ledger 阻断。正常 snapshot 检查资源锁存在、语法、已支持结构、项目身份和稳定版本，不把缺失／无效记录解释为空绑定。已支持的旧 skills/profiles 格式只在 skills 为空时保留为待明确迁移；opaque Profile 历史不自动启用或丢弃。既有迁移测试仍通过。

验证：`pnpm typecheck`、`pnpm test` 222/222 通过。领域测试覆盖损坏 JSON／YAML、原始事务保存、不读敏感或原材料、缺失／过大／不可解码文件、并发变更拒绝、写锁零创建与资源锁缺失／损坏写入拒绝。真实 `node tests/e2e/installed-host-smoke.mjs` 在独立 TEST_ONLY 工作区依次验证配置、ledger、资源锁和事务损坏的只读页面、原始下载内容摘要、写入拒绝，以及原稿和原资料保留。高版本三类原文件查看也同时通过。完整 V1 验收仍在进行。
