# Adoption of an existing Markdown manuscript

Date: 2026-10-05. Implements the existing PRD §2.4/SF-014–016 and SPEC §9.3 requirements. No change to the frozen baseline.

The project first initializes into a new output directory. Draft offers an explicit project-relative `.md`/`.markdown` source, a read-only full-source view, optional citation mappings, and a full before/after adoption preview with backup information. Only the authenticated operator confirmation writes a new manuscript revision. The selected original is never a write target. Current unsaved browser/Host buffers prevent confirmation in the UI; underlying document/config/ledger/reference and original-source hashes prevent stale writes independently of the UI.

The source gateway enforces regular UTF-8 text, a 2 MiB limit, nonempty content, readonly raw-material semantics and owned-path/sensitive-path exclusion. BOM and line endings remain part of the source bytes and snapshot SHA. Invalid encoding, bad paths, future/incompatible projects, unknown citations or changed sources do not create an empty manuscript. The destination uses the normal guarded revision and multi-file transaction, retaining the prior revision, an exact source snapshot and an immutable import manifest with source path/hash, mappings, URL changes, reason, actual session and confirmation time. Interrupted publication recovers once; an old confirmation cannot replay the import after recovery.

Foreign `sf_` keys require an explicit mapping to an existing Source; Core never invents a Source or infers an identity from a number. Other literal keyed/numeric markers can remain as unchanged working-draft text. These produce an unknown citation check, are omitted from automatic BibTeX unless mapped to supported project keys, and block a reviewed-draft claim. A numeric bracket might be an ordinary notation; the report states this ambiguity. Existing source reference sections remain manuscript text. Mapping bibliographic identity does not establish evidence support. Prototype-like marker keys are dictionary data, checked with own-property semantics.

Local selection proposals must preserve supported canonical and legacy marker multiplicity. Partial generic/numeric marker selections fail safely. Detection uses literal text nodes of the positioned Markdown AST, excluding code, math, HTML and escaped brackets. It is a documented bounded syntax recognizer, not a claim to recognize every academic citation format.

AST link/image/definition destinations are located as exact source tokens. Relative targets resolve from the original source directory and are rewritten relative to the new manuscript location, preserving labels, titles, query/fragment and directory semantics. Ambiguous or unsupported token representations fail without guessing. Encoded traversal, credentials, project metadata, absolute private paths and dangerous schemes are refused. HTTPS/mailto and same-document anchors remain unchanged and are not fetched. Adoption does not read or copy linked resources; image export remains separately unavailable until its own verified adapter is implemented.

Tests revealed that micromark drops a leading BOM without counting it in returned offsets. `parseMarkdown` now adjusts every node's UTF-16 offsets back to the unchanged source. Tests and real DOM selection verify the second repeated Unicode paragraph in BOM/CRLF manuscripts. Older sidecars/anchors whose offsets cannot be validated become unknown/need remapping under existing strict checks rather than guessed migration. The review dependency hash now includes `sf-review-v2-bom-and-unmanaged-citations`, making prior evaluator results stale while retaining their immutable files.

Validation: six adoption integrations, four destination/marker unit tests, one BOM selection regression, the complete 278-test suite, type checking, plain installed-Host smoke, and installed-Host live-model smoke. Native evidence covers preview cancellation, explicit foreign-key mapping, original and prior-revision preservation, relative links, actual second-paragraph selection, undo, cold source snapshot, and the existing model workflows. Latest live-model goal used 5 logical calls/1 review round; provider credential files were not copied into the test or printed. Full imported BibTeX ingestion, binary figure export and final V1 signoff remain separate work.
