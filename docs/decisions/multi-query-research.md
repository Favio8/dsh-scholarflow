# 多查询检索与独立结果检查点

日期：2026-10-05。依据 PRD SF-009、SF-010、SF-027、SF-028 与 AT-08、AT-23；SPEC 10.3–10.6、13、29。此记录描述已落地的检索阶段，不声称完整七阶段工作流已经完成。

用户逐条加入查询表达式、研究用途、年份范围和候选数量，整体预览后确认。只向 Crossref 发送查询词、数量与年份；用途保存在项目日志，主稿、资料、文风、记忆和 Skill 不发送，本阶段不调用模型。预览／取消不写项目、不请求网络。

运行按约定保存 run.json、input.json、plan.json、checkpoint.json，使用同一个项目活动运行锁，阻止与未结束写作／审查同时启动。开始及每次请求之前检查权限／预算配置。请求前原子保存查询尝试、累计请求次数和运行检查点；网络等待在写锁外。完整结果或失败与阶段进度原子提交，已成功结果不因后续失败被清空。候选仍需逐条纳入／排除理由，跨查询相同 DOI 沿用既有来源、引用键、身份状态和证据。

查询总预算包括暂时失败的重试和没有应答的中断尝试。候选预算按保存的元数据记录数计算，不因重复 DOI 提前冒称唯一来源；计划各查询上限之和不能超过预算。当前一批最多十二次请求、八十个候选和三十分钟，受项目配置更低上限约束。暂停停止后续调度，当前请求结束后保存；取消传到请求信号，原成功结果与主稿保留。

恢复必须预览、确认并校验原计划、输入、检查点及实际结果，原执行进程存活时不接管。已完成请求复用；中断的无应答请求保留计数并归档为 interrupted，明确恢复后创建新尝试，不能猜测请求未计费。候选用户决定不改变原提供方结果摘要，允许暂停期间用户处理已保存候选。配置变更使旧恢复停止。失败／取消重试创建关联新 run，保留原终态；结束中断只记录用户取消，不修改主稿。

提供方中性、经过验证的临时错误可最多重试两次，等待窗口保存到检查点并在恢复后继续遵守。认证／配置／未知错误不循环。真实安装版 DSH 0.2.0-rc.2 `@deepseek-ai/dsh-web-fetch-http/lib/index.js` 返回 url、statusCode、body、truncated，**没有 HTTP 响应头**。因此 Crossref 429 标为窗口不可用，暂停整批调度，提示用户稍后明确恢复；不虚构 Retry-After 或绕过 Host 使用独立网络客户端。其他可验证的服务状态保留有限重试事实。
