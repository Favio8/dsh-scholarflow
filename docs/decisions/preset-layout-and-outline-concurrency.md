# 预设行布局、重复大纲请求与服务错误诊断

日期：2026-10-10。用户报告预设行文字挤压、连续两次模型请求失败。本轮修复既有布局／取消／去重合同，不改变生成任务范围。

## 证据与原因

预设弹窗位于向导内部，`.sf-wizard button`的固定高度优先于原先只有单类选择器的预设行。两行内容被压进普通按钮高度。预设行现明确拥有自己的自动高度、至少76px命中框、标题／说明间距与行间距；两行说明独立换行。搜索控件也使用弹窗自身的宽度规则。窄屏列表占满可用区域，border-box防止100%宽度再叠加padding后被弹窗裁掉。

只读核对实际阶段审计，发现多次发送给模型的researchData完全一致；最多四个早先的生成请求尚未结束时，后续请求连续以error终态返回零字。之后早先请求仍返回结果并进入审查。这证明存在重复并发及取消失效的问题。旧审计只记录finish:error，未保留failure，因此无法据此断言提供方具体错误是限流、服务故障或其他类型。本轮没有重新发送付费请求。

`outlineInputKey`此前包含封面姓名、学号、日期、封面标题，而这些字段不参与大纲生成；填写封面会误触发新请求。客户端取消RPC也不足以保证旧宿主执行终止。

## 修复

- 自动尝试指纹和候选输入摘要排除封面个人信息，保留封面启用状态；正文题目、要求、材料、篇幅、结构等仍需校验。采用期间保留最新封面值。
- 旧草稿指纹按相同字段结构归一，避免升级本身重放旧请求。
- 宿主`OutlineJobs`按操作者／工作区／会话管理一次执行。相同输入及模型合并；不同输入取消前次，并等待其实际结束，再执行最新请求。即使适配器迟迟不响应abort，也不并发发送替代请求。
- 新增内部`outline.stop`动作与operationId。明确取消通知宿主，早于任务登记的取消有有界记录；旧operationId不取消新任务。卸载时中止执行。
- 生成和图片调用统一保存错误终态的安全事实：code、HTTP status、providerRetryAfterMs；同时覆盖stream返回error和迭代抛异常。不保存原始提供方失败message，避免其回显密钥或完整提示词。按宿主错误分类显示限流、认证、超时、服务异常等，无状态码的RATE_LIMIT也可识别。
- 向导现在真正显示“查看详情”，保留提供方、模型、运行编号和安全错误字段；不再只留下笼统字符串。

## 验证

- 完整分层回归575/575通过；构建与类型检查通过。
- 单测验证15个相同请求只执行一次、忽略abort的旧提供方结束前不启动替代请求、只执行最新排队任务、提前取消、旧取消隔离、旧指纹兼容。
- 实际控制器的受控模型集成测试：15次不同封面个人信息的请求合并成一次生成＋一次审查；采用保留最后的封面字段。
- 浏览器`outline-request-regression.mjs`验证连续填写封面不增加请求、不取消／使候选过期、采用保留数据、错误码和HTTP状态可展开、停止发往宿主。
- 安装版宿主`preset-layout-host.mjs`验证深浅主题×1440/720/390px：标题与说明不重叠、每行内容不越出行底、行间距存在、无页面水平溢出。目视复核发现窄屏列表的padding横向裁切后，使用`--narrow-only`对父容器包围盒做专项验证，两主题通过。日志`.dsh-tmp/preset-layout-host-final.log`、`.dsh-tmp/preset-containment.log`。
- 安装版宿主确认`outline.stop`真实注册并可调用，既有来源读取／重试／提交边界6项通过，证据`.dsh-tmp/preset-stop-host.log`。

模型服务本身的当前可用性未重新实测；本轮修复了已证实的重复请求及取消缺陷，并补齐后续服务错误诊断，不把推测的并发限流写成已确认提供方错误。
