# Project Skill copies and static byte creation

Date: 2026-10-05. Implements existing PRD SF-019/SF-021 and SPEC §16 without changing the frozen baseline.

The operator reads an exact builtin/library/project version, edits the instructions and sidecar routing, previews every resulting file hash, and confirms a new project identity under `.scholarflow/skills/copies/skill_<id>/`. Source bytes and existing bindings stay unchanged. Copying does not enable the new version; enabling uses the existing separate binding preview. Further customization makes another independent tree. Existing runs retain their frozen consumed instructions and references.

The Core `ProjectSkillCopyPlan` freezes the actual source manifest, source instructions, complete copied buffers, destination manifest, project/config/ledger hashes, reason and authenticated source session. Both preparation and confirmation verify the complete package. Confirmation re-reads the original exact version and refuses a stale source/project before publishing bytes. Sidecar replacement is explicit in the preview. The immutable copy history records both manifests, original/current instructions, reason, session and confirmation time.

The installed `@deepseek-ai/dsh-fs` rc.2 public service exposes text mutations only. In the exact installed `@deepseek-ai/dsh-fs-sandbox/lib/index.js`, `SandboxedFileSystem.checkedTarget(target, sandboxPolicy)` is the backend fence used by writeText/editText. It re-resolves workspace-write targets, checks the actual writable roots, and denies read-only. This is a version-pinned backend capability, **not** a portable public binary API. Extraction through `scripts/installed-runtime.mjs` reads the installed ASAR; it does not modify the host. A host without this actual method receives `SKILL_RESOURCE_WRITE_UNAVAILABLE` rather than a native fallback.

`HostFileStore.createResourceBytes` is restricted to private project Skill trees inside the actual project writer lock. Before native directory/file creation it revalidates the project binding, resolves the current session policy again, checks owned canonical containment, rejects links/hardlinks/sensitive paths, and calls the actual backend fence. It creates new files with exclusive open, syncs them, compares native file identity/size, and verifies their bytes through the Host byte reader. It never overwrites an existing file, touches a manuscript/ledger through native IO, loads code, or executes a saved script. It inherits the installed host's accepted narrow path-check/syscall race model; it does not claim kernel isolation against concurrent malicious filesystem mutation.

Files precede the copy-history/ledger transaction and remain unbound until the entire tree passes verification. A crash or cancellation can leave inert new files. These are deliberately retained rather than deleted using guessed ownership; a fresh preview chooses a new destination. The routing sidecar is written last. A complete unbound tree after a crash is still not an enabled binding, and no background repair replays creation or activation. Project copy history and ledger use the existing guarded text transaction.

Five Core integration tests cover byte preservation, independent customization and binding, frozen old input, stale/tampered plans, interruption, fresh destinations and bounds. Three new gateway contracts use an explicitly TEST_ONLY injected policy seam plus actual native files, locks, junctions and hardlinks. They do not substitute for real policy verification. The installed-Host smoke confirms complete binary copying, UI cancellation/customization, unchanged old bindings/resources, cold reads, and actual read-only denial. A first UI test exposed textarea CRLF normalization; the editor now preserves an all-CRLF source's line endings. A permission-test assumption was corrected: persisted sessions retain their own permission mode across restarts, while a newly created session inherits the deployment's read-only default.
