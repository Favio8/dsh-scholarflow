# 要求驱动的大纲与第三步编辑

日期：2026-10-10。对应父目录 PRD/SPEC v1.8，SF-102～106／AT-102～106。用户已确认自动生成候选、确认后采用，强调不得把具体作业硬编码成固定结果。

## 实现

- 新草稿不再自动应用内置议论文预设，空章节只在准备态允许；正式创建仍需非空大纲。预设保留为显式选项，旧草稿章节保持。
- `outline.suggest` 复用宿主当前模型，先读取spec.materials中的有限文本片段，再生成任务理解／章节／逐项要求，随后独立调用模型检查语义覆盖。额外要求须有用户原文quote；确认brief的条目不可遗漏或改名。纯函数校验ID、父链、映射和篇幅，禁止关键词命中代替语义检查。
- 资料只读，上限12个可读片段、每份6000字符、合计24000字符；省略、失败和非全文状态逐项说明。候选保存资料摘要哈希，采用前重新核对，资料改变则拒绝旧候选。
- 自动尝试在请求前同步保存草稿标记；返回、刷新、失败和取消不自动重放。生成时保留原结构，输入变化或手工编辑使迟到结果失效。采用后的新篇幅同时更新去重标记，手工编辑／撤销只使确认失效，不再次自动调用。
- 约N字采用N为规划目标但保留approximate；用户明确保留当前篇幅的覆盖仍优先。手动修改要求时清除旧brief，避免旧任务进入新生成。
- 前置／正文／后置分组，章节重点可展开，多行可编辑；父章移动带子节，子节限制章内移动。正文预算与附属部分分开。`StructureEditor`是实际组件，渲染脚本直接渲染该组件，移除旧的默认议论文静态页面。
- 字数统计优先用大纲kind，防止把分析原论文摘要／参考文献的body章节误当附属部分。旧稿无角色时保留标题回退；review evaluator更新使旧审查记录过期而不改写历史。
