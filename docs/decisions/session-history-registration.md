# 论文会话登记、标题所有权与 v5 日志

日期：2026-10-11。需求依据：上级文档区 PRD／SPEC v1.11、v1.12；用户明确授权插件与宿主共同修复、v5 迁移、更新当前安装。

## 问题与实现

正文写入项目不等于原生会话有聊天轮次。官方 rc.2 的侧栏 `blank` 只观察 `turn/start`，插件直接调用模型的论文会话因此一直显示“新对话”。不能伪造聊天轮次解决登记问题。

宿主新增同进程 `sessionTasks` 服务，ScholarFlow 注册校验器，重新检查真实工作区、会话、项目及已确认任务。登记写入独立 `session/plugin-task-bound` 日志并等待持久化及列表缓存检查点；相同绑定幂等。Session 随事件和恢复 seed 维护登记索引，登记与标题准入读取该状态，不新增弃用的历史扫描。列表投影版本 2 将登记计入正式历史、排序及标题搜索。普通空会话和独立助手不登记。

标题由 `sessionTitle` 服务写入，采用已确认项目标题，无额外模型调用。provider 来源的 task 所有权引用更早的登记，手动重命名采用原生 user 来源并停止同步；异步校验前后核对标题序号，保留并发人工名称。首次登记失败阻止初稿模型启动；已保存标题与侧栏同步失败分别报告。旧任务通过认证修复接口登记，只读检查保持只读。

## 为什么采用 v5

真实冷恢复证明 v4 provider 标题不能使用空真人消息引用。用户选择升级 v5 并提供迁移，替代原先保持 v4 的方案。新增相邻 v4→v5 库及严格任务标题准入，保留 v4 前代原字节。未知旧可忽略同名事件作为外部词汇保留，不冒充真实登记。旧运行时拒绝 v5，不能静默选择过时 v4 前代。

宿主维护分支 `fix/scholarflow-session-tasks` 基于官方 `dsh-v0.2.0-rc.2`，基础提交 `639ed015397290b3745d163aafe02ffee4aa3f84`，修复提交 `a5f570bfcab571f5c77594f195c37e30b32d91c4`。补丁见 `patches/harness-session-tasks-v5.patch`，反向应用检查通过，仅在本地维护，不向官方远端推送。未修改 Agent Loop 运行逻辑；仅移除其两处测试的冗余类型断言以通过当前静态检查。依赖锁保留原版本，只新增迁移库关联。

## 重现与回退

在匹配的 Harness 维护工作树应用补丁，安装锁定依赖并运行其构建及检查。插件仓库执行 `node scripts/package-session-host.mjs <Harness 工作树> <未修改的 rc.2 安装根>` 生成隔离 Windows 包。执行 `node tests/e2e/session-history-host.mjs <修复包根> --legacy-root <未修改的 rc.2 包根>` 验证真实旧格式迁移；不把已经修复的用户安装当旧读取器。

保存并正常退出应用后，使用 `scripts/install-session-host.ps1 -Artifact <隔离包根>` 备份和更新。先前备份仅适用于更新时的数据状态：已有 v5 新工作时须先保留／导出，不能直接用旧日志覆盖。官方更新设置不变；缺登记服务或不支持当前日志格式时，插件提示配套宿主要求，保留正文与原日志。
