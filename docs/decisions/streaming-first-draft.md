# Continuous first draft and post-draft editing

Date: 2026-10-10. [PRD v1.10](../../../docs/ScholarFlow_PRD_v1.10.md) / [SPEC v1.10](../../../docs/ScholarFlow_Design_SPEC_v1.10.md), SF-109–115 / AT-109–115.

## Decisions and behavior

The user selected section-level model calls with progressive paragraph presentation, deferred routine questions, an immediately available first draft without automatic AI revision, preview while generating, immediate cancellation on pause, and one upfront decision to keep selected different files separate. Existing guided tasks keep their behavior; they can explicitly switch from the progress controls. No second agent loop, alternative model SDK or editor replacement was introduced.

The new creation action says “开始生成初稿” and its summary explains the source and publication authorization. The host freezes selected paths and material hashes, audits separate source registration only within that scope, and never merges existing source identities, citation keys or evidence. Modified or newly selected inputs require confirmation. First-draft scheduling retains the approved outline, writes body sections in order and creates summary matter afterward at its original document position. Ordinary clarification, unavailable summaries, invalid claim mappings and unsuccessful section contracts become visible deferred issues or genuine gap paragraphs; authentication, permissions, identity and manuscript conflicts pause with a diagnostic. First-draft completion runs deterministic review and exposes draft readiness, not academic approval. AI checking and all subsequent revision remain explicit actions.

## Streaming and persistence

The existing DSH `ctx.llm.stream` adapter now forwards real text deltas through an optional callback. `@streamparser/json` is pinned to 0.0.26 and decodes only the root replacementText value, including split escapes and surrogate pairs. The complete response still goes through the existing source, section, paragraph-claim and version validation. A complete JSON code-fence envelope is accepted; arbitrary prose is not searched for an object.

The host maintains a current-attempt preview and monotonic sequence, and periodically persists it under the controlled cache. Preview never becomes manuscript or export content. A read-only watch is authenticated and bound to workspace, session, project and task. The client serially reads current snapshots at 250ms while visible and 2s while hidden, using the existing unary RPC; it does not repeatedly inspect full session history or start a model. Observer cancellation is independent of worker cancellation. Closing or refreshing only disposes observation. Late reads and late attempts cannot overwrite newer content.

Pause/stop cancels the request immediately, preserves completed chapters and keeps incomplete text as a separate preview. Explicit resume clears an incomplete child attempt and regenerates only the unfinished section. Main-document changes and unsaved buffers prevent replacement. The editor remains read-only during generation/publication, follows the live position until the user scrolls upward, and offers an explicit return. Routine first-draft problems do not reopen the question overlay.
